# Проверки в браузере

Сквозные проверки интерфейса на телефонном размере (Playwright, Chrome). Работают с локальным стендом и демо-данными, в `pytest` и CI
не входят: им нужен поднятый стек.

```sh
docker compose -p petzy-local -f docker-compose.yml -f docker-compose.local.yml up -d --build
.venv/bin/python scripts/seed_demo.py
.venv/bin/python e2e/run.py            # все проверки
.venv/bin/python e2e/run.py share      # только те, в имени которых есть «share»
```

Что есть:

- `check_documents.py`: документы как архив: строка «Из записи», поиск по записи, клинике и дате;
- `check_feed.py`: лента: запись, пришедшая пока читается следующая страница, не рисуется дважды; круглый «+» отходит при прокрутке вниз;
- `check_medications.py`: лекарства: пропущенный приём назван пропущенным, поздняя доза закрывает нужный приём, два нажатия подряд это одна доза;
- `check_heic.py`: HEIC с телефона рисуется и в Chrome: миниатюра в форме записи и окно кадрирования фото питомца;
- `check_medcard_summary.py`: сводка медкарты, экраны разделов, круглое «+», повтор с записи, заметка о весе;
- `check_medcard_tiles.py`: восемь плиток ровной сеткой, клиника и «Питание и условия» отдельными экранами;
- `check_preparations.py`: любой препарат (вакцина, обработка, лекарство) выбирается одним списком с поиском, смена марки остаётся одной строкой на карте;
- `check_share_link.py`: ссылка для врача: создать, открыть без входа в чистом браузере, PDF, отозвать;
- `check_share_owner_door.py`: та же ссылка у владельца с сессией: копия остаётся копией, но есть кнопка «Медицинская карта»; у ветеринара её нет, и подписи про общие ссылки в Настройках;
- `check_visit_prep_conflict.py`: заметка к приёму, изменённая с двух устройств: второе сохранение отклонено, чужой вариант показан, выбор за человеком;
- `check_weight.py`: экран веса;
- `check_delete_undo.py`: полоса «Отменить»: два удаления подряд отменяются вместе, под полосой нет пустого состояния, пока питомец может вернуться (свой аккаунт, не демо);
- `check_offline_intake.py`: отметка, которую сервер уже записал, сказана, а не потеряна молча;
- `check_draft_per_pet.py`: недописанная запись возвращается тому питомцу, для которого её писали, и только ему; черновик прежней версии переезжает сам;
- `check_scene_background.py`: выбранный цвет фона питомца не мигает при переходе между экранами: фон красит то, что стоит вне проявления, и в кадрах перехода не проступает обычный цвет страницы.
- `check_user_paths.py`: обход всех экранов с заполненным питомцем (38 внутри приложения и 5 без входа). На каждом своё слово, нигде нет текста о сбое и ни один экран не уезжает вбок; пути описаны в [docs/ux/_paths.md](../docs/ux/_paths.md).

Каждая проверка создаёт тестового питомца «Тест-М» (или читает демо-питомца Рекса) и убирает за собой. Вход под `demo` ограничен пятью
попытками в минуту, поэтому `run.py` делает паузу между проверками. Другой адрес стенда: `PETZY_E2E_BASE`.

Пределы писем и регистраций считаются по адресу, а все проверки идут с одного и того же: за час набор тратит норму целиком, и следующий
запустился бы на исчерпанной. Проверка, которой это мешает, начинает с `POST /api/dev/reset-limits` (только локальный стенд). Ждёт
ответов не паузой, а появлением нужного слова на экране: пауза вслепую читает медленный ответ как отказ.

Как ждать: `wait_until(pg, условие)` из `common.py` возвращает текст экрана, когда условие выполнилось. Там, где проверка знает, что
должно появиться (поле, плитка, кнопка, заголовок), ждёт это; там, где проверяется адрес, ждёт адрес. Пауза остаётся только там, где
проверено, что без неё не работает: подъезжающий снизу лист действий или колесо, по которому бьёт палец. Нажатие Playwright и само
дожидается элемента, поэтому отдельная пауза после перехода не нужна.

`run.py` печатает время каждой проверки и пять самых долгих: видно, что ускорять дальше.
