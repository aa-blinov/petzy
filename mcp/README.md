# MCP-сервер Petzy

Подключает ассистента (Claude Code, Claude Desktop и другие клиенты MCP) к дневнику Petzy: посмотреть питомцев, медкарту и ленту, записать событие.

## Что умеет

- `list_pets`: список ваших питомцев.
- `list_event_types`: типы событий и поля, которые нужно заполнить.
- `add_event`: записать событие (вес, кормление, прививку и т. д.). Записи нельзя удалять и менять.
- `get_history`: последние записи из ленты и истории.
- `get_medical_card`: медкарта питомца.

## Доступ

1. Откройте Настройки и раздел «Доступ для ассистентов», создайте доступ. Отметьте только нужные области: «Читать питомцев», «Записывать события», «Читать ленту и историю», «Читать медкарту».
2. Токен показывается один раз. Сохраните его в настройках клиента.
3. Срок доступа: 30, 90 или 365 дней. Доступ можно отозвать в любой момент. Смена пароля и отключение аккаунта отзывают все доступы.
4. Не больше 10 действующих доступов. Лимит: 120 запросов в минуту на один доступ.

## Подключение

Удалённый сервер, адрес `https://petzy.duckdns.org/mcp`. Команда для Claude Code, проверьте синтаксис вашей версии клиента:

```bash
claude mcp add --transport http petzy https://petzy.duckdns.org/mcp --header "Authorization: Bearer ВАШ_ТОКЕН"
```

Локально, через stdin и stdout (для разработки):

```bash
PETZY_TOKEN=ВАШ_ТОКЕН PETZY_API_URL=http://localhost:3000 python -m petzy_mcp --stdio
```

## Что уходит в модель

Всё, что инструмент прочитал, попадает в контекст ассистента и дальше к провайдеру модели. Для медкарты и истории это медицинские данные. Давайте доступ только к тем областям, которые действительно нужны.

## Для разработчиков

- `mcp/petzy_mcp`: клиент к API, инструменты, HTTP-приложение и stdio-режим.
- Сервис `mcp` в `docker-compose.yml`, маршрут `/mcp` в `nginx/nginx.conf` и его копия в `nginx/local-storage.conf`.
- Тесты: `tests/mcp`, проверка на стенде: `e2e/check_mcp.py`.
- Маршрут `/mcp` должен пропускать и внешний (host) nginx на сервере: он вне репозитория.
