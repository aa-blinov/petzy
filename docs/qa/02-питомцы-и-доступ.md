## PET-01. Добавить питомца

- **Шаги:** «Мои питомцы» → «+», выбрать вид, ввести имя, раскрыть «Ещё о питомце», заполнить породу и дату, сохранить.
- **Ожидаем:** Питомец в списке и выбран в шапке.
- **Результат:** ⚠️ проверено частично
- **Как проверено:** вручную: питомец «QA-Питомец» создан с видом «Собака»; в «Мои питомцы» виден новый питомец
- **Не проверено:** выбор нового питомца в шапке вручную не проверяли

## PET-02. Изменить питомца

- **Шаги:** Открыть питомца, «Изменить», сменить имя, сохранить.
- **Ожидаем:** Новое имя в шапке, на ленте и в списке.
- **Результат:** ⚠️ проверено частично
- **Как проверено:** вручную: новое имя «QA-Питомец 2» сохранено на сервере; в «Мои питомцы» виден новый вариант имени
- **Не проверено:** имя в шапке и на ленте вручную не проверяли, только список и сервер

## PET-03. Длинное имя и лишние пробелы

- **Шаги:** Ввести имя длиной около 100 символов с лишними пробелами.
- **Ожидаем:** Имя сохраняется одной строкой с одиночными пробелами, карточка не ломается.
- **Результат:** ✅ проверено
- **Как проверено:** вручную: имя сохранено одной строкой с одиночными пробелами (90 символов); поле ввода держит не больше 100 символов; длинное имя не даёт горизонтальной прокрутки (лишние 0 px)
- **Находка:** QA-05

## PET-04. Оформление питомца

- **Шаги:** Открыть `/pet-look`, выбрать образ, цвет, рамку и подложку, посмотреть карточку и ленту.
- **Ожидаем:** Питомец окрашен своим цветом, кнопки приложения цвет не меняют.
- **Результат:** ✅ проверено
- **Как проверено:** e2e `check_pet_look.py` (9 утв.); e2e `check_accent_contrast.py` (16 утв.); e2e `check_scene_background.py` (5 утв.)

## PET-05. Удалить питомца с отменой

- **Шаги:** Удалить тестового питомца и нажать «Отменить» в плашке.
- **Ожидаем:** Питомец возвращается. Без отмены он уходит окончательно.
- **Результат:** ✅ проверено
- **Как проверено:** вручную: после подтверждения сообщение «удалён» и кнопка «Отменить»; после «Отменить» питомец остался на сервере и через шесть секунд; без отмены питомец удалён с сервера после окна отмены

## PET-06. Пустой питомец

- **Шаги:** Открыть только что созданного питомца без записей: ленту, лекарства, медкарту, историю.
- **Ожидаем:** Везде понятное пустое состояние, без сбоя и без служебных слов.
- **Результат:** ✅ проверено
- **Как проверено:** вручную: /: без служебных значений; /: без сообщения об ошибке; /medications: без служебных значений; /medications: без сообщения об ошибке; /history: без служебных значений; /history: без сообщения об ошибке; /documents: без служебных значений; /documents: без сообщения об ошибке; /medical-card: без служебных значений; /medical-card: без сообщения об ошибке; e2e `check_pets_screens.py` (10 утв.)

## PET-07. Приглашение члена семьи

- **Шаги:** Владелец открывает доступ, вводит логин второго пользователя. Второй пользователь входит и принимает приглашение.
- **Ожидаем:** Приглашённый видит питомца и его записи.
- **Результат:** ⚠️ проверено частично
- **Как проверено:** вручную: «family» получил приглашение от владельца (сохранение формы); у приглашённого на ленте есть приглашение с «Принять»; после «Принять» питомец у приглашённого в списке; pytest `test_share_invites.py` (10 тестов)
- **Не проверено:** записи, которые приглашённый видит в ленте, вручную не проверяли

## PET-08. Выход из доступа

- **Шаги:** Приглашённый выходит из питомца с подтверждением.
- **Ожидаем:** Питомец пропадает у приглашённого, записи остаются у владельца.
- **Результат:** ✅ проверено
- **Как проверено:** вручную: после подтверждения питомец пропал из списка с сообщением «Вы больше не видите»; рядом кнопка «Отменить»; после окна отмены доступ снят на сервере: питомца нет в списке приглашённого; владелец по-прежнему видит питомца
