# Тест-кейсы перед релизом

Кейсы для проверки перед релизом: что человек делает в Petzy, что должно получиться и как мы это проверили.
Каждый кейс записан с результатом, а не только с описанием.

## Что проверяли

- Версия: коммит `a7d3cf4` (`master`), собрано на локальном стенде `petzy-local` (13 октября 2026).
- Стенд: `docker compose -p petzy-local -f docker-compose.yml -f docker-compose.local.yml up -d --build`, демо-данные из `scripts/seed_demo.py`.
- Телефон эмулируется в Chromium (Playwright, headless): ширина 390 px, касания. Настоящий iPhone и Android здесь не участвуют.
- Письма на стенде не уходят наружу: ссылки из них берутся из `/api/dev/outbox` (`MAIL_OUTBOX=memory`).

## Найденное

| Номер | Где | Что не так | Тяжесть |
|---|---|---|---|
| QA-01 | `frontend/src/utils/relativeTime.ts`, `formatRelativeDateTime` | «Добавлен» у документа без времени, если дата документа на день позже даты на часах смотрящего (документ из другой зоны, вечером по его часам). Пример: документ 13 октября 09:44 по Алматы, у смотрящего в Нью-Йорке 12 октября 23:44: выводится «Добавлен 13 октября». Проверка `check_document_file` падает с 15:00 до 24:00 по Нью-Йорку, в этом прогоне упала. По решению владельца в `docs/ux/_decisions.md` время одно для всех. | важно |
| QA-02 | `docs/ux/_paths.md` | Документ ссылается на проверки `check_verify_email` и `check_pending_invites`, их нет в `e2e/`. Утверждения «проверено» по этим экранам не подтверждены автоматикой. | мелочь |
| QA-03 | `frontend/src/pages/DocumentForm.tsx`, поле «Файл» | Файл больше 10 МБ отклоняется сразу при выборе с понятным текстом. После «Добавить» текст меняется на «Выберите фото или PDF», причина пропадает. Тост «Исправьте поле с ошибкой» не объясняет, что именно не так. | мелочь |
| QA-04 | `frontend/src/pages/HealthRecordForm.tsx`, блок `loadError` (около строки 500) | Открытие удалённой записи (например, по старой ссылке) показывает «Запись не загрузилась. Ничего не пропало и не изменилось. Попробуйте ещё раз» с кнопкой «Повторить». Повтор не поможет: записи нет. Для лекарств есть точная формулировка «Такого лекарства нет». | мелочь |
| QA-05 | `frontend/src/pages/HealthRecordForm.tsx`, форма записи веса (шапка с именем питомца) | Очень длинное имя питомца (около 90 символов) на форме записи: пока поле ввода в фокусе (открыта клавиатура), кнопка «Создать» перекрыта этим полем, и нажатие на неё не проходит. Имя из 40 символов не воспроизводит. В эмуляции, на телефоне не проверено. | мелочь |

## Как проверяли

- **Автоматические проверки:** `e2e/run.py`: 54 проверки, прошли 53, не прошла `check_document_file.py` (см. QA-01). `pytest tests/`: 1421 тест, падений 0. В каждом кейсе указано, какая проверка его закрывает.
- **Вручную:** 26 кейсов прошли по шагам на стенде: скрипт открывает приложение в эмуляции телефона, нажимает и вводит как пользователь и сверяет результат с экраном и с сервером. Скрипт в репозиторий не входит: он завязан на тестовые данные локального стенда.
- **Не проверено:** кейсы с ⏭ и причиной ниже. Это то, что на стенде не проверить (телефон, push, админ-аккаунт, большие файлы) или что в этом прогоне не проходили вручную.

## Как запустить снова

```bash
.venv/bin/python -m pytest tests -q --no-cov -n auto
```

```bash
.venv/bin/python e2e/run.py
```

Ручные кейсы по шагам описаны в самих файлах. Новая версия проверяется так же: обновить коммит в шапке, пройти кейсы, которые помечены «вручную» или «не проверено», и записать результат.

Связанные документы: [`docs/ux/_paths.md`](../ux/_paths.md) (пути по экранам, их проверяет `e2e/check_user_paths.py`), [`docs/ios-checklist.md`](../ios-checklist.md) (что проверяется только на телефоне).
